# READIT

READIT opens your documents and reads them aloud in natural voices, on your own device. It highlights each sentence as it is spoken, remembers where you stopped, and keeps working in airplane mode once a voice is downloaded. No account, no uploads.

This repository is **Phase 1 (functional foundation)**: the Android app and the desktop app (Windows first, with Linux and macOS builds). See [docs/FEATURES.md](docs/FEATURES.md) for an exact list of what is implemented, partially implemented and planned.

## What is in the repository

| Path | What it is |
|---|---|
| `core/` | Shared Rust library: document import and extraction, text normalisation for speech, sentence segmentation, the SQLite library. Used by Android through generated Kotlin bindings, and later by the desktop app directly. |
| `android/` | Android app: Kotlin, Jetpack Compose, Media3 background playback, sherpa-onnx offline voices. |
| `android/jvmtest/` | Tests that run the Android reading engine on a plain JVM against the real Rust core. |
| `desktop/` | Desktop app: Tauri 2. `src-tauri/` is the Rust backend (player, voices, audio); `ui/` is the interface (plain HTML, CSS, JavaScript). |
| `samples/` | Test documents generated by `tools/make_fixtures.py` (all written from scratch, free to redistribute). |
| `tools/` | Fixture generator, voice quality checker, JVM test runner. |
| `scripts/` | `fetch-android-deps.sh` and `fetch-desktop-deps.sh`: the native pieces each platform bundles. |
| `docs/` | Features, architecture, voices and licences, privacy policy and voice consent. |

## Build status and what has been verified

Verified in the development environment (Linux, no Android SDK available there):

- 30 Rust tests pass: extraction of every sample format, error handling for encrypted, damaged, unsupported and scanned files, normalisation, segmentation, persistence across restarts, consent rules, erase.
- 24 reading-engine checks pass on the JVM with the real core: full read-through in order, pause and resume, paragraph and page navigation, skip back across sentences, speed and voice changes without losing the place, sleep timer, speaker-notes-only mode.
- Kokoro and Piper voices produce real audio from READIT's extracted text; an offline speech recogniser confirmed the words are present (see docs/VOICES.md).
- The speech-engine code compiles against the real Android SDK and sherpa-onnx classes.

**Not yet verified:** the full Android build (Compose screens, Media3 service, WorkManager) has not been compiled here because Google's Maven repository is blocked in that environment. The first GitHub Actions run, or a local Android Studio build, is the first full compile. Expect to fix small compile issues on that first build.

### Desktop app (verified here, on Linux)

- 11 desktop tests pass: the same playback scenarios as Android, plus voice catalogue, archive safety and audio resampling.
- End to end with real voices: the 3-page sample PDF was read start to finish (32 sentences) by Kokoro and Piper through the desktop player. An offline speech recogniser found 96% (Kokoro) and 94% (Piper) of the content words in the audio.
- The release `.deb` (83 MB) and AppImage (155 MB) were built. The `.deb` was installed and run with a clean environment: it found its bundled PDF engine and offline voice, imported a PDF passed on the command line, read it aloud with the highlight following, and downloaded and installed a second voice from inside the app.
- **Not yet verified:** the Windows installer. It can only be built on Windows; the GitHub Actions workflow `desktop.yml` builds it on a Windows runner.

## Run the core tests

```bash
# PDFium for your platform from https://github.com/bblanchon/pdfium-binaries (chromium/7881)
export READIT_PDFIUM_DIR=/path/to/pdfium/lib
pip install python-docx python-pptx reportlab ebooklib pypdf pillow
python3 tools/make_fixtures.py
cd core && cargo test
```

Reading engine on the JVM (needs `kotlinc` 2.2 and `jna-5.17.0.jar`):

```bash
KOTLINC=kotlinc JNA_JAR=/path/to/jna.jar tools/jvm-test.sh
```

## Build the Android app

### Option A: GitHub Actions (recommended)

Push this repository to GitHub. The workflow in `.github/workflows/android.yml` runs the tests, builds the core for three Android ABIs with the NDK, and produces:

- `app-debug.apk`: install directly on a phone (allow "Install unknown apps").
- `app-release-unsigned.apk` and `app-release.aab`: sign before publishing.

Download them from the run's **Artifacts** section.

### Option B: on your laptop

Requirements: Android Studio (Ladybug or newer) with SDK 35 and the NDK, Rust (`rustup`), and Git Bash or WSL on Windows.

```bash
export ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/<version>   # Windows: %LOCALAPPDATA%\Android\Sdk\ndk\<version>
scripts/fetch-android-deps.sh                              # speech engine, PDFium, core .so files, bindings
cd android
./gradlew assembleDebug                                    # Windows: gradlew.bat assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

Or open the `android/` folder in Android Studio after running the script and press Run.

### Signing a release

Create a keystore once (`keytool -genkeypair -v -keystore readit.jks -alias readit -keyalg RSA -keysize 4096 -validity 10000`), keep it out of the repository, then build with:

```bash
READIT_KEYSTORE=/path/readit.jks READIT_KEYSTORE_PASSWORD=... READIT_KEY_ALIAS=readit READIT_KEY_PASSWORD=... ./gradlew bundleRelease
```

## Build the desktop app

### Windows installer

Option A: push to GitHub; the **Desktop** workflow produces `READIT_0.1.0_x64-setup.exe` (per-user install, no admin rights needed) and an `.msi` under the run's Artifacts.

Option B: on a Windows PC with [Rust](https://rustup.rs), [Node.js 20+](https://nodejs.org), Git for Windows and the Visual Studio C++ Build Tools:

```bash
# in Git Bash, from the repository folder
scripts/fetch-desktop-deps.sh windows      # PDFium + the bundled offline voice (Piper Cori, public domain)
cd desktop
npm ci
npx tauri build --bundles nsis msi
# installer: desktop/src-tauri/target/release/bundle/nsis/READIT_0.1.0_x64-setup.exe
```

The installer includes one offline voice, so READIT can read aloud straight after installation without internet. More voices download from inside the app. The speech engine is linked statically, so there are no extra DLLs.

### Linux

```bash
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev libasound2-dev libxdo-dev
cd desktop/src-tauri && cargo build --release && cd ../..   # downloads the speech engine libraries
scripts/fetch-desktop-deps.sh linux
cd desktop && npm ci && npx tauri build --bundles deb appimage
```

### Develop

```bash
export READIT_PDFIUM_DIR=/path/to/pdfium/lib   # optional during development
cd desktop && npm ci && npx tauri dev
```

Keyboard: Space play/pause, Left/Right skip, Up/Down paragraph, Page Up/Down page, [ and ] speed, B bookmark, Ctrl+F search, Ctrl+O open, Alt+1 to Alt+5 switch screens. Files can be dropped onto the window or passed on the command line ("Open with").

## First run on a phone

1. Open READIT. The built-in phone voice works immediately.
2. Voices tab: download **Kokoro natural voices** (126 MB) or a **Piper** voice (64 MB). Tap **Test** on a voice: READIT measures whether it keeps up on your phone.
3. Home > Open a document, or share a file to READIT from WhatsApp, Files, Gmail or a browser.
4. Press play. Lock the phone: reading continues with lock-screen and Bluetooth controls.

## Troubleshooting

| Problem | Fix |
|---|---|
| `libpdfium.so` or `libreadit_core.so` not found at runtime | Run `scripts/fetch-android-deps.sh` before building; check `android/app/src/main/jniLibs/<abi>/`. |
| Gradle cannot find `sherpa-onnx-1.13.8.aar` | Same script; it downloads into `android/app/libs/`. |
| `cargo ndk` fails | Set `ANDROID_NDK_HOME` to an installed NDK (r26 or newer). |
| Speech pauses between sentences | The voice is too heavy for that phone; use Voices > Test and pick Piper or the phone voice. |
| Desktop: "The secure connection to the download server could not be verified" | A work firewall is inspecting HTTPS. READIT trusts the computer's own certificate store, so installing the company's root certificate in Windows fixes it; otherwise allow github.com. |
| Desktop: "No sound output was found" | Connect speakers or headphones, or select an output device in the system sound settings, then press play again. |
| Words missing from Kokoro audio | Do not upgrade sherpa-onnx to 2.0.0: it skips words not in Kokoro's dictionary. Stay on 1.13.8 until fixed upstream. |
